# Spring AI 概览

Spring AI 是 Spring 官方为 Java 开发者打造的**企业级生成式 AI 开发框架**。

如果用一句话概括它的本质：**Spring AI 就是 Java 生态里的“AI 统一接入桥梁”**。正如 `Spring Data` 用统一的接口屏蔽了 MySQL、PostgreSQL、MongoDB 等底层数据库的差异，`Spring AI` 让你可以用同一套优雅的 Java 代码，自由切换 OpenAI、Claude、DeepSeek、Qwen 或本地的 Ollama 大模型。

## 💡 为什么需要 Spring AI？  

在 Spring AI 出现之前，Java 开发者对接 AI 模型面临三大痛点：

1. **厂商锁死**：直接调用各家 SDK（OpenAI、Anthropic 等），更换模型需要重构大量代码。
2. **胶水代码多**：处理 Prompt 拼接、JSON 结构转换、向量检索（RAG）需要手工编写大量重复逻辑。
3. **缺乏企业级抽象**：缺乏统一的拦截处理、上下文记忆管理和可观测性监控。

Spring AI 借鉴了 LangChain 与 LlamaIndex 的核心思想，但**并非简单移植**，而是完全基于 Spring 生态的原生设计模式（自动配置、链式 API、AOP 思想、声明式组件），让企业级 Java 应用接入 AI 变得极其顺畅。

---

## 🧩 核心知识点全景拆解

### 1. 多模型统一抽象 (Portable Model API)

Spring AI 提供了覆盖全模态的统一接口：

* **Chat Model**：文本对话与推理（支持 OpenAI、Anthropic、DeepSeek、Google GenAI、AWS Bedrock、Ollama 等）。
* **Embedding Model**：将文本转化为高维向量（支持 PGvector、OpenAI、VertexAI 等）。
* **Image / Audio / Moderation Model**：提供图像生成（DALL-E、Stability）、语音识别（Whisper）、文本转语音（TTS）以及内容安全审核能力。

> **通俗类比**：驱动模式——切换 AI 模型就像在 `pom.xml` 中切换数据库驱动，核心业务代码一行不用变。

---

### 2. ChatClient API（流式/链式客户端）

类似 Spring 的 `RestClient` 或 `WebClient`，`ChatClient` 提供了极其优雅的 Fluent（链式）API：

```java
String response = chatClient.prompt()
    .user("请用简短的语言解释什么是量子计算？")
    .advisors(new MessageChatMemoryAdvisor(chatMemory)) // 自动注入历史对话记忆
    .call()
    .content();

```

* **支持响应式流（Streaming）**：通过 `.stream()` 轻松对接 Server-Sent Events (SSE)，实现打字机效果。
* **默认配置与模板复用**：支持设置默认 System Prompt、默认工具等。

---

### 3. Structured Output（结构化输出）

大模型默认返回非结构化的文本，但在业务开发中我们通常需要标准的 Java 对象（POJO/DTO）。

* **运作原理**：Spring AI 会在 Prompt 后自动追加格式规范提示词，并捕获模型的 JSON 响应，自动反序列化为指定的 Java 实体类。
* **使用体验**：通过 `.entity(MyDTO.class)` 即可直接拿到类型安全的 Java 对象，彻底告别复杂的正则匹配和手动解析。

---

### 4. Function Calling / Tools（工具与函数调用）

大模型不是全知全能的，它不知道当天的天气、内部数据库的库存，也无法直接下订单。

* **工具调用的本质**：给大模型装上“手和脚”。你将标准的 Java `@Bean` 函数注册给 Spring AI，当模型判断需要外部数据时，会**反向请求** Java 执行该方法，并将方法返回的结果作为上下文继续推理。
* **动态工具发现**：支持在运行时根据上下文动态寻找并挂载可用工具。

---

### 5. RAG 与 ETL 数据管道 (Retrieval Augmented Generation)

RAG（检索增强生成）是让 AI 能够“结合企业私有知识库答题”的关键技术。Spring AI 提供了完整的离线+在线链路：

| 阶段 | 组件名称 | 作用描述 | 生活类比 |
| --- | --- | --- | --- |
| **离线阶段 (ETL)** | `DocumentReader` | 从 PDF、Word、JSON、网页等提取原始文本 | 图书搬运工 |
|  | `DocumentTransformer` | 文本切块（Chunking）、数据清洗与元数据标注 | 切菜加工 |
|  | `VectorStore / Writer` | 调用 Embedding 模型生成向量，写入向量数据库 | 归类入库 |
| **运行阶段 (Runtime)** | `VectorStore` | 根据用户提问，做向量相似度检索（支持类 SQL 过滤） | 借书检索 |
|  | `Augment & Generate` | 将检索到的知识与用户问题拼装成 Prompt 送给 LLM | 带着参考资料答题 |

* **向量库支持**：原生支持 PGvector、Redis、Milvus、Pinecone、Elasticsearch、Chroma、Qdrant 等 20+ 种主流向量数据库。

---

### 6. Advisors API（拦截器与顾问机制）

设计灵感来源于 Spring AOP 和 Spring MVC 的 HandlerInterceptor。

* **功能**：在请求发送给 LLM 之前、以及响应返回给客户端之后进行**切面拦截**。
* **常见应用场景**：
  * **Chat Memory**：自动维护和裁剪多轮对话的历史上下文。
  * **RAG 自动增强**：在提问发出前自动去向量库检索相关文档并补全上下文。
  * **安全与审计**：敏感词过滤、Token 消耗统计、响应日志记录。



---

### 7. Model Context Protocol (MCP) 与 Agent

Spring AI 深度集成了Anthropic 主导的 **MCP 协议**。

* **MCP 的意义**：MCP 是 AI 时代的“USB 接口”。通过 MCP，Spring AI 应用不仅可以作为**客户端**调用外部的 MCP 服务（如 GitHub、Slack、数据库连接器），也可以作为**服务端**将现有的 Spring 业务能力暴露给其他 AI Agent，是构建复杂自主 Agent 系统的重要基石。

---

### 8. 企业级保障：可观测性与测试

* **Observability**：集成 Spring Boot Observability (Micrometer / Zipkin / Prometheus)，可以清晰监控每次 AI 调用的 Token 消耗量、响应延迟、提示词模版命中率等指标。
* **Testcontainers 集成**：可以在单元测试和集成测试中快速拉起本地向量数据库（如 PGvector、Milvus），保证测试环境的高保真与自动化。

## ⚡ 一句话速记卡片

> **Spring AI = 统一的模型 API + 流式 ChatClient + 自动化结构化输出 + 声明式 Function Calling + 完整 RAG/ETL 管道 + AOP 式 Advisor 拦截 + MCP 智能体协议。**
